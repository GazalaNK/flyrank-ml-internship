CTR/Engagement Opportunity Scoring on Real Search Data

Ranking pages that under-capture clicks relative to their search position — an applied search intelligence capstone

Gazala Nikhat Kittur · FlyRank ML Internship · Lane 4: CTR / Engagement Opportunity Scoring

Abstract

This project asks which visible pages under-capture clicks relative to their search ranking position, and whether that gap can be scored and ranked usefully for a content reviewer. The method compares actual click-through rate (CTR) against the expected CTR for a page's position tier, computes a residual, and ranks pages by how far below expectation they fall. A transparent baseline rule was built first, then a Random Forest regression model was trained on the same features and evaluated under a client-grouped validation split to avoid leakage across pages belonging to the same client. 1. Introduction

FlyRank's Refresh product surfaces pages that may need attention, including a "CTR Fix" trigger for pages that are visible (enough impressions, a reasonable position) but underperform on clicks relative to expectation. The decision this capstone supports is: which visible pages should a content reviewer look at first, given limited time, when the concern is under-captured clicks rather than declining visibility. The action that follows a high-ranked page is a metadata, snippet, or content review — not an automatic rewrite. The cost of a wrong recommendation is wasted reviewer time on a page that was never actually a problem, which is why this capstone treats ranking quality (not raw accuracy) as the metric that matters.

2. Data

This project uses the FlyRank ML Internship warehouse release on Hugging Face (FlyRank/internship-warehouse), specifically the fact_content_daily_performance fact table, joined implicitly through pseudonymized content_hash_id and client_hash_id keys — no raw client names, domains, URLs, or queries were ever present in this dataset.

  • Table: fact_content_daily_performance (daily grain, aggregated to one row per content page for the month)
  • Time window: one mid-panel month, March 2026 (month=2026-03), deliberately avoiding the _sample table, which represents the final sealed month and would leak future information into any label-like logic
  • Filter: rows with gsc_data_available = TRUE only, and pages with zero impressions excluded (CTR undefined)
  • Excluded by design: any FlyRank product-computed fields (health_score, priority_score, action_type) were never used as features, to avoid the model simply learning to reproduce FlyRank's existing rule rather than finding independent signal

3. Methodology

3.1 Unit of analysis and target

One row represents one content page, aggregated over the March 2026 window: total impressions, total clicks, and average search position. The target is a CTR residual: actual CTR (clicks ÷ impressions) minus the median CTR of pages in the same position tier (tiers: 1–3, 4–10, 11–20, 20+). A large negative residual indicates a page ranking well but under-capturing clicks relative to peers at the same position — the definition of a review candidate for this lane.

3.2 Baseline

The baseline is a transparent scoring rule, not a model: score = −1 × CTR residual, filtered to pages with at least a minimum impression threshold to avoid rewarding low-volume noise. Reason code: ctr_below_tier_expectation. Action label: review_metadata_and_snippet. Two signals behind this rule were independently verified before trusting it: CTR-vs-position (directly behind FlyRank's own CTR-fix logic) and impression volume (behind the "quick win" logic) — both confirmed as real, observable relationships in this data slice, not assumed.

3.3 Model

A Random Forest regression model was trained to predict the CTR residual directly from observed features (impressions, clicks, average position), rather than converting the problem into classification — preserving the continuous nature of the ranking signal. Random Forest was chosen over linear regression because the relationship between position, volume, and CTR is plausibly non-linear and involves feature interactions a linear model would miss.

3.4 Validation design

A client-grouped split was used rather than a random split: pages belonging to the same client were kept entirely within either the training set or the test set, never both. This matters because pages from the same client can share site-wide patterns (template, domain authority, niche) that a model could memorize rather than genuinely generalize from — a random split risks leaking client identity into the "unseen" test set and inflating apparent performance. This was verified directly: a naive random split was compared against the client-grouped split on the same data (Section 4), and client overlap between train and test was measured explicitly under both.

3.5 Leakage audit

  • All features (impressions, clicks, average position) are observed signals known before any review decision — none are calculated after the fact.
  • The feature window and target window are the same observed month; there is no forward-looking window in this baseline, so no future-leakage risk applies here.
  • No FlyRank product-computed flag was used as a feature at any point.
  • Client overlap between train and test was explicitly measured under both the random split and the client-grouped split (Section 4) to confirm the grouped split eliminates this leakage path.

5. Limitations and Honest Framing

  • This analysis covers one month (March 2026) of one dataset slice; results are observed and directional on this data, not a guarantee of generalization to other months or the full warehouse.
  • The comparison shows the model's ranking outperforming the baseline rule's ranking on this test split — this is decision-support for a human reviewer, not a guarantee that acting on any single recommendation will improve that page's performance.
  • This method ranks candidates for review; it does not establish that a metadata or content change will cause a CTR improvement. Any causal claim would require an explicit experiment, which this data alone cannot provide.
  • Position-tier expectations were built from a single month and a subset of clients with available GSC data; they may not generalize across seasons or to clients with different tracking history.

6. Ranked Recommendations

The model produces a ranked review queue (work/outputs/baseline_action_score.csv, regenerated on each notebook run) of pages ordered by predicted CTR gap. Each entry includes a reason code and a suggested action (metadata/snippet review). The top 20 were manually reviewed for volume sufficiency and plausibility before being treated as trustworthy recommendations; entries with borderline impression counts or unusual position outliers were flagged as lower-confidence.
